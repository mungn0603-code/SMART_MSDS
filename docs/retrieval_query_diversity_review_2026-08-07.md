# Retrieval 테스트셋 질의 다양성(Template Bias) 검토 보고서

**작성일**: 2026-08-07 (§9 추가: 재측정 후 갱신)
**대상**: `04_rag_agent/evalset/gold_pair.jsonl` (383쌍, 청석면 제외 후)
**결론 선요약**: 단일 템플릿 구조에서 **템플릿 단어가 정답 청크에 13.7~51.6% 리터럴
중복**됨을 확인해(§4) 어휘 편향 가설을 세웠고, Ground Truth 유지 + Query 5개 다양화를
권고(§6~8)했다. **실제 재측정 결과(§9)는 이 가설과 반대** — 전체 평균 Recall@10·
nDCG@10이 오히려 상승했고, 부분 breakdown(2/5 템플릿)에서도 리터럴 중복 없는 템플릿이
더 높게 나왔다. 가설은 기각 방향이나 표본이 적어(환경 문제로 5개 중 2개만 측정)
확정은 아니다 — §9 참고.

## 1. 현재 테스트셋 구조 평가

`evalset_pairs.py`가 생성하는 질의는 전부 단일 템플릿이다.

> "{물질A}, {물질B} 두 물질을 함께 취급해도 되는가? 혼합 시 위험성과 유의사항은?"

물질명(A, B)만 치환되고 문장 구조·어휘는 365쌍 전부 동일하다. Ground Truth는 물질별
섹션2(GHS분류)·섹션10(피해야 할 물질) 청크 조합으로, 질문 의도와 매칭 자체는 정확하다.
구조적으로는 **"1 topic(물질쌍) → 1 query → 1 gold" 형태**이며, IR 문헌에서 흔히 쓰는
"1 topic → N query variants → 1 gold" 형태가 아니다.

## 2. 장점

- Ground Truth(섹션2·10) 선정 근거는 명확하고 질문 의도와 정합적 — 이 부분은 문제 없음
- 물질명 자동 치환이라 365쌍 전체를 스크립트로 일괄 생성·검증 가능 (재현성 높음)
- 단일 템플릿이므로 지표 간 비교가 "물질 조합 자체의 난이도" 차이만 반영 — 노이즈 원천이 하나로 통제됨(장점이자 §3의 단점의 이면)

## 3. 문제점

1. **어휘 편향(lexical bias) 가능성** — 템플릿의 "취급", "혼합", "위험성" 등이 정답 청크
   원문에도 등장한다면, BM25(희소 검색) 성분이 실제 의미 이해가 아니라 표면적 단어
   일치만으로 정답을 맞힐 수 있다. 이 프로젝트는 hybrid(dense+BM25 RRF)를 채택했으므로
   (`decisions.md` §2.4) 이 리스크가 실측치에 직접 반영된다.
2. **템플릿 과적합(template overfitting)** — 임베딩 모델이 이 특정 문장 구조에서만
   잘 작동하고 실제 사용자의 다양한 어투(구어체/사무체/안전문의형)에서는 성능이 다를 수
   있는데, 지금 구조로는 이 차이를 관측할 수 없다.
3. **질의 분포 편향(query distribution bias)** — 실사용자는 "같이 보관해도 되나요?",
   "반응 위험 있나요?" 등 다양하게 물을 것이다. 단일 템플릿은 이 분포의 한 점만 표본
   추출한 것이라 일반화 근거로는 약하다.
4. **임베딩 편향(embedding bias)은 상대적으로 낮음** — dense 임베딩은 표층 어휘보다
   의미 벡터에 더 의존하므로 위 1번보다는 영향이 작을 것으로 추정된다(단, 완전히 면제는
   아님 — §5 로버스트니스 문헌 참고).

## 4. 자체 데이터 검증 (추측 아님, 실측)

정답 청크(gold_section) 124개(365쌍 중 30쌍 샘플)의 원문에 템플릿 단어가 리터럴로
등장하는 비율을 직접 조회했다.

| 템플릿 단어 | 정답 청크 내 등장 비율 |
|---|---:|
| 위험성 | 51.6% |
| 취급 | 42.7% |
| 혼합 | 13.7% |
| 유의사항 | 0.0% |
| 함께 | 0.0% |

**"위험성"이 정답 청크의 절반, "취급"이 42.7%에서 리터럴로 일치한다.** 이는 BM25가
질의-정답 간 의미적 유사성이 아니라 표면 단어 일치만으로도 상당 부분 정답을 맞힐 수
있다는 뜻이며, 현재 hybrid 실측치(Recall@10 0.9005 등, `HANDOFF.md` §0)가 이 리터럴
중복의 도움을 어느 정도 받았을 가능성을 배제할 수 없다. 반대로 "유의사항", "함께"는
전혀 등장하지 않아 이 두 단어는 편향 기여가 없다 — 템플릿 전체가 아니라 **"위험성"·
"취급" 두 단어가 편향의 주 용의자**다.

## 5. Retrieval 연구 관점 평가 및 근거 문헌

### 5.1 대형 벤치마크의 다양성 확보 방식 — "topic 간" 다양성이지 "topic 내" 다양성이 아니다

- **BEIR** (Thakur et al., 2021, NeurIPS Datasets & Benchmarks, [arXiv:2104.08663](https://arxiv.org/abs/2104.08663)):
  18개 데이터셋·9개 태스크(질의응답, 사실검증, 중복질문검색, 개체검색, 뉴스, 논증,
  트윗, 바이오메디컬 등)를 이질적으로 조합해 zero-shot 일반화를 측정한다. 다양성의
  단위는 **데이터셋/도메인 간**이며, 동일 정답에 대해 여러 패러프레이즈를 붙이는 구조는
  아니다.
- **MTEB** (Muennighoff et al., 2023, EACL, [arXiv:2210.07316](https://arxiv.org/abs/2210.07316)):
  BEIR를 포함해 8개 태스크·58개 데이터셋으로 확장. 마찬가지로 데이터셋 간 이질성이
  다양성의 원천이다.
- **MS MARCO**: Bing 실사용 로그에서 익명화 샘플링한 100만+ 개의 실제 사용자 질의.
  질의당 정답은 희소(약 1개/질의)하며, 각 질의는 **서로 다른 실제 사용자**가 자연스럽게
  작성한 것이라 결과적으로 어휘가 다양하지만, 이는 "동일 정답에 여러 패러프레이즈를
  의도적으로 배치"한 설계가 아니라 **대규모 실사용 로그의 자연 발생적 다양성**이다.

**시사점**: BEIR/MTEB/MS MARCO 모두 "질의 하나당 정답 하나"라는 이 프로젝트의 구조
자체는 표준적이다. 다만 이들의 다양성은 **수십만~수백만 개의 서로 다른 topic**에서
나오지, 365개 topic 각각을 단일 문장으로 고정하는 데서 나오지 않는다. 이 프로젝트는
topic 수가 작으므로(365쌍) topic 간 다양성만으로는 부족하고, topic 내 질의 다양성
보강이 상대적으로 더 중요하다.

### 5.2 "동일 topic에 여러 질의" 설계의 선례 — UQV100

- **UQV100** (Bailey, Moffat, Scholer, Thomas, SIGIR 2016, [Microsoft Research](https://www.microsoft.com/en-us/research/publication/uqv100-a-test-collection-with-query-variability/)):
  TREC 2013/2014 Web Track에서 뽑은 100개 topic에 대해 크라우드워커 263명에게 각
  topic의 "정보 요구 배경 스토리"를 읽히고 실제로 쓸 법한 질의를 작성하게 해 **총
  10,835개 질의**(정규화·중복제거 후 5,764개 고유 변형, topic당 평균 약 58개)를
  수집했다. **이 컬렉션이 만들어진 이유 자체가 "단일 질의로 시스템을 비교하면 순위가
  질의 표현에 따라 뒤집힐 수 있다"는 문제의식**이다. 즉 "1 topic → N query variants →
  동일 Ground Truth" 구조는 IR 평가 방법론에서 **이미 검증된 정석 설계**이며, 이번
  요청(N개 질의, 동일 정답)과 정확히 같은 발상이다.

**시사점**: Ground Truth를 유지하고 Query만 다양화하는 방향은 UQV100의 설계 원칙과
부합한다. 다만 UQV100은 topic당 약 58개라는 크라우드소싱 규모이며, 이 프로젝트
포트폴리오 MVP 규모에는 그대로 적용할 수 없다(§6에서 실용적 규모 논의).

### 5.3 Dense/Hybrid 검색의 질의 변형 민감도

- Dense 검색 로버스트니스 서베이([arXiv:2211.14876](https://arxiv.org/pdf/2211.14876) 등
  관련 문헌): 질의 변형을 **구문 변화형**(오탈자, 자연스러움, 어순, 패러프레이즈)과
  **의미 변화형**(일반화/특수화, 관점 변화)으로 구분하며, 패러프레이즈 질의에서 원 질의
  대비 평균 약 20% 성능 하락이 보고된다. Dense 검색기가 희소 검색(BM25)보다 질의 변형에
  더 민감하다는 것이 반복 관측되며, **dense-sparse 융합(hybrid)이 순수 dense보다
  로버스트니스가 높다**는 결과도 있다 — 이 프로젝트가 hybrid를 채택한 결정(§2.4)과
  방향은 맞지만, 그 hybrid의 BM25 성분이 §4에서 확인한 어휘 중복의 수혜자일 수 있다는
  점은 별개로 검증해야 한다.
- **"How You Ask Matters! Adaptive RAG Robustness to Query Variations"** (2026,
  [arXiv:2604.10745](https://arxiv.org/abs/2604.10745)): RAG 파이프라인에서 **의미가
  동일한 표층적 질의 변화만으로도 검색 행동과 정답 정확도가 크게 흔들린다**는 것을
  대규모 벤치마크로 보임. 모델 크기를 키워도 이 로버스트니스 갭은 해결되지 않는다 —
  "지표가 좋으니 안전하다"는 가정이 성립하지 않을 수 있음을 시사.

### 5.4 이 프로젝트가 이미 채택한 RAGAS의 설계 원칙과의 정합성

`decisions.md` §2.8에서 RAGAS를 RAG 평가 프레임워크로 이미 채택했다. RAGAS의 테스트셋
생성기는 애초에 **페르소나·질의 길이·질의 스타일**을 조합해 단일 템플릿을 피하도록
설계되어 있다("evolutionary" 생성 방식으로 reasoning/conditioning/multi-context 변형
등을 만듦). 즉 이번에 지적된 문제는 이 프로젝트가 이미 도입하기로 결정한 도구의 기본
철학과도 어긋난다 — RAGAS 도입 시점에 자연스럽게 해결됐어야 할 부분이 retrieval 평가셋
쪽에는 아직 반영되지 않은 상태.

## 6. 개선 권장안

1. **Ground Truth는 그대로 유지** — §5.2 UQV100 선례와 정확히 부합하는 설계이므로
   바꿀 이유 없음.
2. **질의를 3~5개로 다양화**. 10개(UQV100 topic당 58개에야 근접하는 크라우드소싱
   규모)는 이 프로젝트 규모에 과함 — Ground Truth가 바뀌지 않는 이상 5개를 넘어가면
   한계효용이 급격히 준다(같은 두 청크를 겨냥하는 문장을 늘릴수록 얻는 정보는 "평균의
   노이즈 감소"뿐, 새로운 검증 축이 아님). 반대로 1개는 §5.3의 20% 성능 낙폭 리스크를
   전혀 관측 못 한다. **3~5개가 신호 대비 비용의 현실적 절충점**.
3. **어휘 중복 최소화를 다양화의 명시적 기준으로 삼는다** — §4에서 "위험성"(51.6%),
   "취급"(42.7%)이 정답 청크에 리터럴로 중복됨을 확인했다. N개 템플릿 중 **최소 1~2개는
   이 두 단어를 의도적으로 피해서** 작성해야 진짜 의미 기반 검색 성능을 분리 측정할 수
   있다(§7 예시에서 표시).
4. **비용은 무시할 수준** — 질의 임베딩 1건 501.7ms(`HANDOFF.md` §5 실측)이므로 365쌍
   ×5템플릿=1,825질의 재임베딩은 약 15분. 검색 자체는 0.089~6ms 수준이라 무관.
   리랭커까지 5배로 돌리면 134분(369쌍 기준 실측)×5가 되어 부담이 커지므로, 다양화
   재실측은 **리랭커 미실행 상태(hybrid만)로 먼저 돌리는 것을 권장**.
5. **재측정 시 비교 지표는 "템플릿별 개별 Recall"이 아니라 "topic당 N개 질의의
   평균/분산"** — UQV100 방법론처럼 topic 내 분산이 클수록 그 topic은 어휘 의존적
   정답일 가능성이 큼(진단 신호로 활용 가능).

## 7. 실제 적용 가능한 Query Template 예시

기존 문의(B절 10개 예시)에서 register가 서로 다르고 어휘 중복이 적은 것 위주로 5개
선정. 현재 템플릿은 1번으로 유지(비교 기준선 보존).

| # | 템플릿 | register | "위험성"/"취급" 포함 여부 |
|---|---|---|---|
| 1 (기존) | {A}, {B} 두 물질을 함께 취급해도 되는가? 혼합 시 위험성과 유의사항은? | 사무/보고서체 | 둘 다 포함 (기준선) |
| 2 | {A}와 {B}를 같이 보관해도 안전한가요? | 구어체, 저장 맥락 | 미포함 |
| 3 | {A}와 {B}가 접촉하면 위험한가요? | 안전문의형 | "위험" 포함(변형), "취급" 미포함 |
| 4 | {A}와 {B}는 반응할 가능성이 있나요? | 화학반응 직접 질의 | 둘 다 미포함 |
| 5 | {A}와 {B}를 분리해서 보관해야 하나요? | 부정/역질문 프레이밍 | 둘 다 미포함 |

4개(2~5)는 "위험성"·"취급" 리터럴을 의도적으로 배제해 §4에서 확인된 어휘 편향과
독립적으로 실제 검색 성능을 관측할 수 있게 설계했다. 3번은 "위험"이라는 부분 문자열이
남아 순수 통제군은 아니라 참고용으로만 쓴다.

## 9. 추가(Addendum, 2026-08-07 재측정 후) — 실제 재측정 결과, 가설과 반대

권고안 반영 후 실측한 결과, **전체 평균은 오히려 상승**했다(Recall@10 0.9005→0.9234,
nDCG@10 0.8932→0.9104, 질의 임베딩 지연도 501.7→368~395ms로 개선). 상세 수치는
`HANDOFF.md` §0-1.

템플릿별 개별 breakdown은 환경 세그폴트로 5개 중 2개(t0, t1)만 완료됐다:

| 템플릿 | 리터럴 중복 | Recall@10 | nDCG@10 |
|---|---|---:|---:|
| t0(기존) | "위험성"·"취급" 포함 | 0.9149 | 0.8990 |
| t1("같이 보관해도 안전한가요?") | 미포함 | **0.9503** | **0.9347** |

**§4의 어휘 편향 가설과 반대 방향**: 편향 위험이 없는 t1이 오히려 t0보다 높게
나왔다. 표본 2개뿐이라 단정할 수 없으나, "리터럴 중복이 검색 성능을 부풀렸다"는
당초 우려는 이 두 표본에서는 반증됐다. bge-m3-ko 임베딩(dense 성분)이 표면 어휘보다
의미에 더 강하게 반응한다는 §5.3 문헌의 일반론과는 부합하는 방향 — hybrid의 BM25
성분이 우려한 만큼 리터럴 중복에 의존하지 않았을 가능성. t2~t4까지 완료해야 확정
가능(§8 권고는 유지 — 진단 신호로서 템플릿 다양화 자체의 가치는 여전함, 다만
"편향이 있다"는 가설은 지금까지 데이터로는 지지되지 않음).

t2~t4 미완료 원인은 재현 가능한 환경 세그폴트(`HANDOFF.md` §0-1 참고, 후속 세션 과제).
