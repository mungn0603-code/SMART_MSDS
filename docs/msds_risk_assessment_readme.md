# MSDS 위험성평가 자동화 파이프라인 (RAG+Agent) — 계획 README

작성일: 2026-07-30 상태: **기존 구현 파일 전부 폐기. 이 문서가 유일한 기준점(single source of truth)이다.** 성격: 계획/설계 문서. 코드 구현 없음. 실행은 별도 세션(Claude Code)에서 이 문서를 기준으로 진행한다.

## 1\. 문제 정의 & 목표

KOSHA MSDS(물질안전보건자료) 데이터를 기반으로, 화학물질 간 반응성 위험을 RAG+Agent 구조로 자동 평가하는 시스템을 만든다. 화공 도메인 지식과 AI/RAG 엔지니어링 역량을 동시에 증명하는 포트폴리오 프로젝트이며, 상업적 목적이 아닌 연구/포트폴리오 목적이다.

핵심 제약: 매트릭스 기반 판정은 참고 자료일 뿐 **단독 최종 판정 근거가 될 수 없다** — 이 원칙은 이 문서 전 구간에서 반복 적용된다.

## 2\. 현재 확정된 파이프라인 스코프 (5단계)

| Stage | 내용 | 방식 확정 |
| :---- | :---- | :---- |
| 1 | MSDS 원본 수집 (KOSHA API) | 4핵심섹션(2 위험성분류/3 구성성분/9 물리화학적특성/10 안정성·반응성), 200\~400종 |
| 2 | 반응성 그룹 분류 | 규칙기반(키워드/정규식) 우선, LLM은 보조 — arXiv:2606.11204 근거(LLM 단독 84%, 90% 문턱 미달) |
| 3 | 반응성 그룹 간 양립성 매트릭스 구축 | CAMEO 68그룹 체계, 2,346쌍(68×69/2) |
| 4 | RAG/Agent 판정 레이어 | 순서: 분류 → 본문추출 → 청킹 → 임베딩 → 적재검증 (사용자 지시, Claude 해석 매핑 — 최종 확인 대기 ◻) |
| 5 | 평가/응답 생성 | 근거 등급제(법령\>권고\>참고) \+ Abstain(기각) 정책 적용 |

이 스코프 자체는 07/29\~07/30 세션에서 여러 차례 검토를 거쳐 확정된 것으로, **임의로 재변경하지 않는다.** 변경이 필요하면 반드시 사유를 명시하고 사용자 확인을 받는다.

## 5\. 다음 실행 계획 (계획만 — 구현 없음)

1. **원본 데이터 확보 및 배치**: 위 §4 표의 항목들을 사용자가 작업 폴더에 투입한다.  
2. **원본 구조 탐색**: xlsm/CSV의 실제 시트명·컬럼·인코딩을 먼저 확인한다 (68개 그룹명이 실제로 존재하는지 이 단계에서 최초 검증됨). 구조를 가정하지 않는다.  
3. **반응성 매트릭스 자동 변환 설계**: 68개 그룹 표준화 → Incompatible/Caution/Compatible → RED/YELLOW/GREEN 코드 변환 → 대칭성·완전성(2,346쌍) 자동 검증. 수작업 입력은 배제하고 스크립트 기반 자동 변환을 원칙으로 한다.  
4. **DB 스키마 설계 확정**: `reactivity_groups`(68개), `compatibility_matrix`(2,346쌍), 기존 EAV 기반 `msds_items` 구조 유지, `extracted_features`에 `evidence_tier`(LAW/RECOMMENDATION/REFERENCE) 컬럼 추가 설계.  
5. **타겟 물질 200\~400종 교차대조 설계**: CAMEO CAS-그룹 라벨 × KOSHA 매니페스트 교집합 → 그룹별 배분 → CAS 리스트 확정 (KOSHA 매니페스트 확보 전까지 실행 불가, 설계만 선행 가능).  
6. **에이전트 판단 정책 스키마 설계**: disclaimer는 코드 상수로 관리(DB 저장 방식 배제 — 문구 변경 시 마이그레이션 부담 회피), Abstain 정책은 `agent_response_log` 형태의 응답 로그 테이블로 설계.  
7. **Claude Code 핸드오프**: 위 1\~6이 설계 수준에서 사용자 확인을 받으면, 그때 비로소 실행 담당(Claude Code) 세션에서 실제 코드/DB를 만든다. 이 README는 그 세션의 출발점 역할을 한다.
