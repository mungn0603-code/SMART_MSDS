# 기술/설계 결정 기록 (Decision Log)

이 문서는 프로젝트 전반의 **철학**과 **개별 기술 선택의 근거**를 한곳에 모은다. 각 결정에는
근거 유형을 명시한다 — **실측**(이 프로젝트에서 직접 측정) / **사용자 지정**(실측 없이
결단) / **외부 출처**(문서·논문 인용, 신뢰도 별도 표기) / **구조적 논증**(데이터 구조상
자명함).

세부 실측 수치와 원본 근거는 `docs/HANDOFF.md`, `docs/stage4_design_changes_2026-08-06.md`,
`docs/HANDOFF_ARCHIVE.md`를 참조. 데일리 로그는 `docs/PROJECT_LOG.md`.

## 0. 이 프로젝트의 메타 원칙

### 0.1 "실측 vs 사용자 결단"을 항상 구분해서 기록한다
**결정**: 모든 설계 변경에 대해 근거가 데이터 실측인지, 사용자가 실측과 무관하게 내린
결단인지를 구분해 기록한다. 실측과 최종 결정이 어긋나는 경우에도 결정을 실측 쪽으로
조용히 맞추지 않고, **충돌 사실 자체를 문서에 남긴다**.
- **근거 유형**: 프로젝트 운영 원칙(메타 결정)
- **출처**: 자체 수립
- **실제 적용 사례**: §3.5 (Dense vs Hybrid) — hybrid가 핵심 KPI(Recall@10)를 포함해
  7개 목표 중 6개를 충족했음에도 성능이 더 좋은 dense를 채택했고, section filter 적용 후 hybrid가 더 높은 성능을 기록해 재수정했다. 실측을 왜곡하지 않고 기록해 앞으로의 방향성에 영향을 끼친다.

### 0.2 최상위 우선순위: 검색 성능 > 유지보수성 > 확장성 
**결정**: Stage 4(RAG) 설계 v2에서 확정. "기존에 써봤다"는 사실 자체는 채택 근거가
될 수 없고, 재사용은 성능이 동률일 때만 고려한다.
- **근거 유형**: 사용자 결단(철학 교체)
- **출처**: 자체 수립
- **배경**: 원래 v1은 정반대 철학("(KDIC 프로젝트) 재사용 우선")으로
  출발했으나, 2026-08-06 전면 교체됐다. v1은 폐기하지 않고
  `archive/design_docs/`에 "왜 재사용 우선을 버렸는지 비교 대조용"으로 보존.
  **철학 자체를 뒤집고 그 이유와 이전 버전을 그대로 남긴 것**은 의도적
  선택이었다.

### 0.3 비협상 원칙 4종 (프로젝트 시작부터 불변)
1. 양립성 매트릭스 조회 결과를 **단독** 최종 판정 근거로 사용 금지 — 참고자료일 뿐.
2. CAMEO 최신 68그룹 체계 엄격 적용(구 EPA 41그룹 폐기).
3. 근거 부족 시 **Abstain** — 억지로 답변하지 않는다.
4. 근거 등급제: 법령(Mandatory) > 권고(Recommended) > 참고자료(Reference).
- **근거 유형**: 사용자 결단 / 원 출처는 EPA 매트릭스 원문의 "단독 판정 금지" 경고 계승
- **출처**: EPA-600/2-80-076 원문 경고 문구

## 1. 도메인 / 데이터 결정

### 1.1 CAMEO 68그룹 체계 채택 (구 EPA 41그룹 폐기)
- **결정**: 반응성 분류 체계로 CAMEO의 최신 68그룹을 쓴다.
- **근거**: 41그룹은 CAMEO가 이후 68그룹으로 확장하기 전의 구버전 — 최신 체계를 쓰지
  않을 이유가 없음.
- **근거 유형**: 구조적 논증(더욱 검증된 최신 자료)
- **출처**: CAMEO/EPA 공개 자료

### 1.2 타겟 물질 스코프: 200종 (3,386종 전체 풀 확대안 기각)
- **결정**: 학부 실험실 커버리지 기준 200종 유지. CAS 매핑으로 확보된 3,386종 전체
  풀로의 확대는 미채택.
- **근거**: API quota(개발 계정 기준 1,000콜/일 가정치), MVP 스코프 유지. 3,386종 확대 아직 미채택. 하지만 KOSHA 운영계정 신청 시, 일일 트래픽 100000 사용 가능. 
- **근거 유형**: 사용자 결단(2026-08-04)
- **출처**: 공공데이터포털 물질안전보건자료 조회 서비스
- **트레이드오프**: 200종은 68/68 CAMEO 그룹을 전부 커버하지만, 그룹당 대표성은
  1~수종 수준. 통계적 일반화보다 "그룹 커버리지 완전성"을 우선한 설계.

### 1.2a 반응성 기본물질(물·산소·범용 산/염기 등) 보강 — Stage 5 후보로 보류
- **결정**: 지금 당장 추가하지 않는다. Stage 4 잔여 과제(RAG 지표·Abstain 측정) 완료
  후 "핵심 반응성 기본물질 20~30종 보강"을 Stage 5 후보로 별도 트래킹한다.
- **근거**: 섹션10 "피해야 할 물질"에 물·산소·일반 산/염기류가 상대 물질로 압도적으로
  자주 등장해 조합 평가 기능의 실사용 커버리지에 기여할 것으로 보이나, 이는 KOSHA API
  추가 수집 + CAMEO 재분류가 필요한 **신규 수집 범위**이며 현재 진행 중인 지표 측정
  작업과 무관하다. 우선순위상 뒤로 미룸.
- **근거 유형**: 구조적 논증(섹션10 등장 빈도 추정) — 실측 아님, 실제 빈도는 미검증
- **출처**: 없음
- **관련**: §1.2(200종 스코프 결정)와 별개 축. 200종은 "학부 실험실 커버리지" 기준이고
  이 항목은 "조합 상대방으로 자주 나오는 기본물질" 기준이라 선정 근거가 다름.

### 1.2b CAS↔CAMEO 그룹 매핑 데이터 소스 전환: CAMEO 웹 스크레이핑 → PubChem 기반 (robots.txt 준수)
- **결정**: `chemicals`/`chemical_group_membership`(3,386종/6,657행) 확보에 썼던
  `cameochemicals.noaa.gov` 검색 결과 페이지 직접 스크레이핑을 **폐기 대상으로
  확정**하고, 신규/재수집은 PubChem의 공식·비차단 엔드포인트 조합으로 전환한다.
- **근거**: 기존 스크레이핑 경로는 CAMEO `robots.txt`의 `/search` 계열 disallow를
  위반해 확보된 데이터로, 포트폴리오 취약점(방어 필요 항목)으로 이미 식별돼 있었다.
  2026-08-07 파일럿(기존 수동검증 12종 대조)으로 대체 경로를 실측 검증:
  - **CAS→CID**: `https://pubchem.ncbi.nlm.nih.gov/rest/pug/compound/name/{CAS}/cids/JSON`
    — 공식 PUG-REST, NCBI 문서(`/docs/pug-rest`)에 명시된 프로그래매틱 접근 경로.
  - **CID→CAMEO 68그룹**: `https://pubchem.ncbi.nlm.nih.gov/classification_2/classification_2.fcgi?hid=86&search_uid={cid}&search_type=list&search_uid_type=cid&format=json`
    — PubChem Classification Browser가 브라우저에서 직접 호출하는 JSON 엔드포인트
    (Chrome 네트워크 탭으로 실측 확인). **PUG-REST/PUG-View 공식 문서에는 없는
    비공식·미문서화 엔드포인트**이나, robots.txt에 disallow 항목이 없어 접근 자체는
    막혀있지 않다. HID(hierarchy id)는 핸드오프 문서가 가정한 80(현재는
    "PubChem BioAssay Classification")이 아니라 **86**("CAMEO Chemical Reactivity
    Classification")이 정답 — `hid=index` 조회로 확인.
  - **파일럿 결과**: 12종 중 11종 일치(에탄올은 CAMEO 설계상 다중그룹 소속이라
    "Acids, Weak"+"Alcohols and Polyols" 등 4개 그룹 모두 반환 — 정상), 1종
    (티오황산나트륨, 무수/오수화물 둘 다 확인)은 PubChem 미러에 CAMEO 매칭 없음
    (커버리지 갭, 오답이 아니라 결측).
  - **부수 발견**: 파일럿 대조 중 기존 DB의 UREA 레코드(수동 보강분,
    `02_classification/fix_missing_common_chemicals.py`)가 CAS `497-19-8`로
    잘못 등록돼 있었음을 확인 — 이 번호는 실제로는 **탄산나트륨(Sodium Carbonate)**의
    CAS이고, 요소(UREA)의 올바른 CAS는 `57-13-6`(PubChem CID 1176)이다. 스크레이핑
    데이터에는 이미 `57-13-6`으로 정확히 들어있어(chemical_id 2160, group 12
    "Amides and Imides") **완전 중복 레코드**였던 것으로 확인 — 삭제 대상
    (chemical_id 3398).
- **robots.txt 재확인 — 완전 무결은 아님, 방어 논리로 정확히 서술할 것**:
  `pubchem.ncbi.nlm.nih.gov/robots.txt`의 `User-agent: *` 그룹은 `/rest/pug/`를
  명시적으로 disallow한다(단, `/classification_2/`는 disallow 목록에 아예 없어
  전면 허용). NCBI가 `/rest/pug/`를 PUG-REST라는 이름으로 별도 공식 문서화하고
  요청 제한(throttling) 정책까지 공개해 프로그래매틱 API 클라이언트의 사용을
  전제로 설계·운영한다는 점에서 "검색엔진 크롤링 차단"과 "문서화된 API 호출"을
  구분하는 것이 통상적 해석이지만, robots.txt 원문 텍스트만 보면 100% 깨끗한
  주장은 아니다 — CAMEO 스크레이핑(검색결과 HTML을 사람 대상 UI 우회로 긁던 것)
  보다는 방어 가능성이 훨씬 높으나, 발표 시 이 뉘앙스를 숨기지 말고 그대로 밝힐 것.
- **아직 안 한 것 (add when)**: 3,386종(또는 200종 타겟) 전체에 대한 PubChem 기반
  재수집/교차검증 스크립트는 아직 작성되지 않았다 — 이번 결정은 **경로 전환
  자체의 확정**이며, 대량 재수집 실행은 별도 세션 과제로 남긴다(속도 제한 고려한
  배치 스크립트 필요, PUG-REST 권장 처리량 초당 5회 수준).
- **근거 유형**: 실측(파일럿 12종 대조) + 사용자 결단(robots.txt 준수를 위한 소스 전환)
- **출처**: `pubchem.ncbi.nlm.nih.gov/robots.txt`, `/docs/pug-rest`, Classification
  Browser 네트워크 요청 실측(2026-08-07)

  PubChem의 근본적 커버리지 범위 밖 |
| 신규 `chemical_group_membership`(source=pubchem_verified) | 46 | 다중그룹 소속
  신규 확인분 |

**요약**: 3,396종 중 실질 문제(결측+CID실패) **204종(6.0%)** — 전부 §1.2c 그룹
대표물질 폴백 로직(`02_classification/group_fallback.py`)의 적용 대상이고,
전부 구조적으로 설명 가능한 PubChem 커버리지 한계(혼합물/고분자/광물/총칭명)이지
우리 조회 코드의 결함이 아니다. **결론: CAMEO 68그룹 매핑의 94%는 이제
robots.txt를 준수하는 공식 경로로 재확보/교차검증됐고, 남은 6%는 원리적으로
"단일 화합물 CID 체계"인 PubChem으로는 못 채우는 영역**(혼합물·고분자 등)이라
추가 시도의 기대효익이 낮다 — 이 6%에 한해서만 기존 CAMEO_scrape 데이터를
단독 근거로 유지하는 것이 합리적. 상세 원본: `01_collection/pubchem_verification_report_full.csv`.

### 1.2c 데이터 수집 단계 결측/불일치 허용 + 그룹 대표물질 폴백 (2026-08-07)
- **결정**: PubChem 기반 재수집(§1.2b)에서 특정 CAS가 CID 조회 실패, CAMEO 무매칭,
  또는 기존 스크레이핑 그룹과 불일치로 나오는 경우 즉시 Abstain 처리하거나 데이터를
  강제 정정하지 않는다. **수집 단계**에서는 이런 결측/오류를 허용하고, 해당 물질이
  조합 판정에 필요해지는 시점에 **같은 CAMEO 그룹의 다른 대표 물질** 데이터로 대체
  참조하는 폴백을 둔다.
- **적용 범위 — §0.3 원칙 3(근거 부족시 Abstain)과의 계층 구분**: 이 결정은 **수집/매핑
  단계**에만 적용되고, **최종 반응성 판정 단계**(`compatibility_engine.py`,
  §2.10)의 Abstain 원칙은 그대로 유지된다. 즉 "이 물질 자체의 그룹 정보가 없다"는
  이제 즉시 Abstain 사유가 아니라 "같은 그룹 대표물질로 대체 조회를 먼저 시도하고,
  그마저 실패해야 Abstain"으로 한 단계 완화된다 — 두 원칙이 서로 다른 레이어에서
  작동하므로 충돌이 아니다.
- **구현 완료 (2026-08-08)**: `02_classification/group_fallback.py`
  `get_fallback_candidates(cas_number)`. cas_number의 소속 group_id를 조회 →
  같은 그룹의 다른 물질을 **KOSHA MSDS 4개 섹션 확보 여부(`msds_sections`
  존재 여부) 우선 정렬**로 최대 3건 추천. cas_number 자체가 그룹 매핑조차
  없으면 빈 리스트(= 폴백 불가, Abstain 대상 — §0.3 원칙 3과 여기서 다시 만남).
  자체검증(`__main__`, assert 3건) 통과.
  - **적용 결과**: §1.2b 199종 실행에서 나온 문제 10종(PubChem 무매칭 1 + CID
    조회실패 9) 전부에 대해 실행 — **10종 전부 같은 그룹 내에 이미 KOSHA MSDS를
    확보한 대체 후보가 3건씩 존재**함을 확인. 즉 이 10종은 당장 재수집 없이도
    같은 그룹 대표물질로 실사용 가능 — 급한 블로커 아님.
  - **의외의 발견**: `docs/HANDOFF.md`에 "대체 후보 소진"으로 기록됐던 디아조늄염
    2종(135072-82-1, 15005-97-7)에 대해 이 함수를 돌려보니, 199종 **타겟리스트
    밖의 전체 3,386종 풀**에는 같은 그룹(Diazonium Salts) 물질이 더 있음
    (15557-00-3, 21723-86-4). "소진"은 199종 **타겟리스트 내부**에서만 사실이었고
    전체 풀 기준으로는 아니었다 — 다만 이 2종은 KOSHA MSDS가 미확보 상태라
    즉시 대체하려면 신규 KOSHA 수집이 필요(§4-6 3,386종 확대 작업과 연결).
- **근거 유형**: 사용자 결단
- **출처**: 없음

### 1.2a-upd 반응성 기본물질(물·산소·범용 산/염기 등) 보강 — 로드맵 활성화 (2026-08-07)

### 2.3 검색공간 축소: 섹션 §2·§10 필터 (805→409청크)
- **결정**: 반응성 판정 질의는 §2(유해성분류)·§10(안정성·반응성)만 검색 대상으로 좁힌다.

  청크가 정답 자리를 빼앗고 있었음(오답의 37.8%가 "질의에 등장한 물질의 다른 섹션").
  필터 적용 후 Recall@10 +1.59%p, nDCG@10 +3.68%p, 검색 지연 3.3배 단축 — **정확도와
  속도가 동시에 개선된 순수 이득**.
- **근거 유형**: **실측** (이 프로젝트에서 근거가 가장 강한 결정)
- **출처**: 없음(자체 실측), 상세 수치는 `docs/stage4_design_changes_2026-08-06.md` §1

### 2.4 검색 방식: Hybrid 재채택 (Dense 단독 결정 철회)
**현재 상태(최신)**: **Hybrid(dense+BM25 RRF) 채택.** 
§0.1 원칙에 따라 순서대로 남긴다.

1. **1차 결정(2026-08-06, §2.3 필터 적용 전)**: FAISS dense 검색만 쓰고 BM25+dense
   RRF 하이브리드는 폐기. 제시된 사유는 레이턴시.
2. **충돌 발견**: §2.3(섹션 §2·§10 필터) 적용 **후** 재실측하니 같은 조건에서 hybrid가
   Recall@10 0.9005(dense 0.8829보다 +2.0%p), nDCG@10·MRR도 hybrid 우세. 레이턴시
   차이는 6.19ms로 사용자가 직접 정한 예산(Retrieval ≤ 10ms) 안에 들어옴. **7개 목표
   중 hybrid 6개 충족, dense는 4개.** 원인은 1차 결정이 §2.3 필터 적용 **이전** 데이터
   (당시 hybrid 열세)에 근거했기 때문 — 필터 적용으로 BM25 성능이 크게 개선(MRR
   0.73→0.98)되며 근거 데이터가 갱신됐는데 결정은 따라가지 못한 것.
3. **재검토 후 철회 및 재채택(현재)**: 필터 적용 후 실측이 일관되게 hybrid 우세를
   가리키고, 레이턴시 사유도 예산 안에 들어온다는 점이 이미 §2.3 단계에서 확인돼
   있었으므로 dense 단독 결정을 철회하고 hybrid로 전환. 코드 변경:
   `04_rag_agent/run_ab.py`의 `evaluate_reranker()`가 하이브리드 후보를 dense로
   바꿔치기하던 부분(`h = d` 우회, 1차 결정의 흔적)을 되돌려 실제 hybrid 순위(`h`)를
   리랭커 입력으로 쓰도록 수정.
- **근거 유형**: 실측(1차 결정만 사용자 결단, 재채택은 실측 근거로 복귀)
- **출처**: 없음

### 2.5 평가 과제 재정의: 단일물질 사실조회 → 물질 쌍 (목표 스코프의 최소 단위)
- **결정**: 초기 평가셋(단일물질 사실조회 407건, 예: "아세톤의 인화점은?")을 버리고
  물질 쌍 369건(Incompatible 135/Caution 114/Compatible 120)으로 교체.
- **근거**: 제품이 실제로 받는 입력은 **2종 이상 다중 물질**이지, 단일 물질 사실조회가
  아니다 — MSDS를 그냥 읽으면 나오는 값을 되묻는 평가셋으로는 제품 성능을 검증할 수
  없다는 설계 오류를 뒤늦게 인지.
- **스코프 정확화**: "쌍(2종)"은 다중 물질 스코프 **그 자체가 아니라 최소 단위**다.
  N종(N≥3) 조합 판정 로직은 §2.10에서 이 쌍 판정을 재사용해 구현됨. 단, RAG 검색
  계층 실측(§2.3, §2.4)은 여전히 쌍(2종) 질의 기준뿐이라는 점은 구분할 것 — §2.10 참고.
- **근거 유형**: 설계 오류 정정
- **출처**: 없음
- **보존**: 단일물질 평가셋은 검색기 부품 점검용(`--task fact`)으로 남겨둠 — 버리지
  않고 용도를 재정의.

### 2.10 다중 물질(N≥2) 판정: 쌍 전수분해 + 3계층 리포트 — **구현 완료 (2026-08-07)**

#### 문제 재정의
실험실에서 실제로 쓰는 물질은 흔히 3종 이상이다. 처음 설계(위쪽 초안)는 "N종 전체를
worst-case 한 마디로 요약"이었는데, 실사용자가 원한 건 그게 아니었다 — **① 입력한
물질 각각이 뭔지 간단한 프로필, ② 물질끼리 매핑됐을 때 어떤 반응이 나는지 전부,
③ 그 반응들의 유의사항을 쌍별로 따로 볼 수 있어야 한다.** 하나의 점수로 뭉개면
"셋 중 뭐가 문제인지"가 안 보인다. 그래서 worst-case 요약은 "빠른 결론" 용도로만
남기고, 실제 주력 출력은 **전부 보여주는 쪽**으로 다시 짰다.

#### 왜 N종 전용 데이터를 새로 안 만들었나
CAMEO 원자료 자체가 그룹×그룹 **쌍** 매트릭스(68×68)다. N종 전용 반응성 표는
어디에도 없다. 만들려면 그룹 3개 조합만 68C3 = 50,116가지 — 실측도, 출처도 없는
값을 새로 채워 넣어야 한다. 이건 **원칙 1(근거 없는 판정 금지)**·**원칙 3
(근거 부족시 Abstain)** 정면 위반이다. 그래서 N종 데이터를 새로 만드는 방향은
애초에 검토 대상에서 제외.

#### 채택한 방식: 쌍 전수분해 + worst-case + 3계층 리포트
1. **분해**: 입력 N종을 중복 제거한 뒤, 가능한 모든 쌍 C(N,2)로 쪼갠다
   (`itertools.combinations`). 3종이면 3쌍, 5종이면 10쌍.
2. **판정 재사용**: 쌍 하나하나는 기존 §2.5의 `judge_pair_by_cas(cas_a, cas_b)`를
   **그대로** 호출한다 — 새 판정 로직을 만들지 않았다. Abstain 처리, 근거등급
   (Reference 고정), 면책고지, "그룹 여러 개 소속시 그룹조합 전수평가 후
   worst-case" 로직까지 전부 기존 함수에서 상속된다. 이유: 물질 하나가 그룹 여러
   개에 속할 때 "그룹조합을 전수평가해 worst-case로 합친다"는 패턴이 이미
   `judge_pair_by_cas` 안에 있었다(그룹 레벨). 물질 N개를 물질쌍으로 전수평가하는
   건 그 패턴을 물질 레벨로 한 단계 그대로 올린 것뿐 — 새 개념이 아니다.
3. **결과를 하나로 뭉개지 않고 3계층으로 분리**:
   - **`SubstanceProfile`** (물질별 프로필): CAS, 이름, 소속 CAMEO 그룹. "이 물질이
     뭔지"만 보여준다. `chemicals`/`chemical_group_membership` 테이블 조회 재사용
     (`resolve_cas_to_groups`, 기존 함수). MSDS 원문 유해성 문구(GHS H/P코드 등)는
     여기서 안 끌어옴 — 그건 04_rag_agent가 다루는 영역이라 스테이지 경계를
     넘지 않기로 함(과설계 방지). 필요해지면 그때 그 계층과 연결.
   - **`to_table()`** (전체 매트릭스): N×N 마크다운 표, 칸 값은 category
     문자열 그대로(Compatible/Caution/Incompatible/Abstain). 색만 입히면 히트맵
     완성 — 프론트 없는 지금 단계에서는 실제 렌더링(matplotlib 등) 없이 이
     데이터 형태까지만 제공(YAGNI, 아래 "안 한 것" 참고).
   - **`pair_reports()`** (쌍별 상세): 쌍마다 독립된 블록으로 사유, 그룹쌍
     유의사항(`compatibility_pairs.description`/`hazard_codes_raw`/`gas_products_raw`),
     그 쌍에 한정된 abstain 경고를 따로 묶는다. UI 카드 하나씩으로 바로 쓸 수 있는
     단위.
   - **`full_report()`**: 위 셋 + 면책고지를 프로필→표→쌍별상세 순서로 이어붙인
     완성 리포트. 세 조각은 독립적으로도 쓸 수 있게 분리 유지(합치기만 하는
     레이어라 삭제해도 나머지는 안 깨짐).
   - **worst-case 단일 category**는 버리지 않고 유지 — "전체적으로 안전한가?"
     한마디가 필요한 소비자(예: 상단 배지 표시)를 위한 요약값으로 남겨둠.
4. **종합 순위**: `_VERDICT_RANK = {Compatible:0, Abstain:1, Caution:2, Incompatible:3}`.
   Abstain을 Compatible보다 위에 두는 이유 — "모른다"가 "확인된 안전"보다 덜
   위험하다고 말할 근거가 없다. 반대로 Incompatible/Caution처럼 **확정된 위험
   신호가 하나라도 있으면 그게 항상 이긴다** — 불확실성(Abstain)이 확정된
  위험 신호를 가리면 안 되기 때문. abstain_notes는 worst-case에 안 뽑혀도
   전부 취합해 살려둔다(침묵 금지 원칙, §0.3).
5. **입력 정리**: 중복 CAS는 자동 제거(`set`). 고유 CAS가 1개 이하로 남으면
   `ValueError` — "조합"이 성립하지 않는 입력이라는 신호.

#### 근거 유형·출처
구조적 논증(기존 코드 패턴의 직접적 연장) + 실사용자 요구사항 반영(worst-case
단일값 → 3계층 리포트로 전환). 출처: 없음.

#### 검증 (자체 테스트, `compatibility_engine.py` `__main__`)
- 중복 제거 후 1종만 남으면 `ValueError` (테스트 4)
- 3종 입력(중복 1개 포함) → 중복 제거 후 정상 판정 (테스트 5)
- 3종 중 미등록 CAS 1개 섞임 → 그 쌍만 Abstain, 나머지 Incompatible 쌍이 있으면
  worst-case는 Incompatible로 이기되 abstain_notes는 살아있음 (테스트 6, rank
  로직 실측 검증)
- 실물 3종(황산·아세톤·과산화수소) → `full_report()`가 프로필 3개, 매트릭스 3×3,
  쌍별 리포트 3건을 정상 생성 (테스트 7)
- 전부 실제 DB(`reactivity_reference.db`)로 재현 가능, mock 없음.

## 4. 아직 검증되지 않은 가정 / 포트폴리오 발표 시 주의할 지점

미완성 상태를 감추지 않는 것이 이 프로젝트의 원칙(§0.1)과 일관된다.

1. **arXiv:2606.11204의 84%/90% 수치**(§1.3): 존재·주제는 확인됐다는 기록이 없고,
   원문 대조 검증도 안 됨. 발표 자료에 이 수치를 쓸 계획이면 먼저 원문을 열람할 것.
2. **EPA 매트릭스 "단독판정 금지" 원문 출처**(§0.3): 프로젝트 파일 어디에도 원문
   URL/문서번호가 남아있지 않다. 원칙 자체는 계승했지만 1차 출처를 다시 찾아 링크를
   보강할 필요가 있음.
3. ~~RAG 지표(Faithfulness 등) 전체 미실행~~ **(파일럿 완료, 2026-08-07)**(§2.8):
   n=7 파일럿 실측 완료(Faithfulness 0.51 / Context Precision 0.40 / Context Recall
   0.74 / Answer Relevancy 0.47, `HANDOFF.md` §4-2). 표본이 작고 Faithfulness·Context
   Precision·Answer Relevancy가 낮게 나와 **긍정적으로 포장하면 안 됨** — n을 늘려
   재확인 전까지는 "생성 품질에 실제 개선 여지가 있다"는 신호로 다뤄야 한다.
